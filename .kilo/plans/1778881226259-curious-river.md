# Frontend UI/UX Audit & Remediation Plan

## Project: Pedigree PRO
**Date:** 2026-05-15  
**Scope:** Complete frontend codebase audit covering CSS, JavaScript/TypeScript, accessibility, responsive design, component architecture, performance, visual consistency, and code quality.

---

## Executive Summary

The Pedigree PRO frontend is a well-structured React + Vite + Tailwind application with a solid shadcn/ui foundation and commendable recent improvements (accessibility tests, self-hosted fonts, `noUnusedLocals`, virtualized timelines). However, **95 inline style instances**, **widespread missing `type="button"`**, **hardcoded colors bypassing the theme system**, **large monolithic components**, and **performance anti-patterns** significantly detract from the application's professional quality. This plan addresses all findings in order of severity.

---

## 1. CRITICAL SEVERITY FINDINGS

### C1. Widespread Missing `type="button"` — Accessibility & Functional Bugs
**Impact:** Buttons inside forms or ambiguous contexts default to `type="submit"`, causing unexpected submissions and keyboard navigation failures.  
**Files Affected:** 23 files, 100+ occurrences  
**Key Locations:**
- `RibbonToolbar.tsx` — lines 142, 157, 160, 172, 173, 186, 190, 205, 207, 219, 221, 233, 235, 253, 258, 264, 276, 282, 287, 294, 299, 304, 318, 325, 335, 345, 353, 361, 377, 387, 395, 415, 424, 430, 441, 451, 483, 485, 493, 495, 503, 539, 544, 567, 571, 578, 590, 596, 615
- `ContextMenu.tsx` — lines 116, 117, 118, 120, 123, 126, 129, 136, 141, 146, 151, 156, 162, 167, 175, 179, 183, 189, 193, 204, 208, 211, 215, 218, 222, 228 (all menu items)
- `NodeEditModal.tsx`, `PropertiesPanel.tsx`, `FindBar.tsx`, `pedigrees.tsx`, `patients.tsx`, `profiles.tsx`, `LanShare.tsx`, `VersionTimeline.tsx`, `VersionHistoryPanel.tsx`, `RiskCalculatorPanel.tsx`, `ImportDialog.tsx`, `ShareModal.tsx`, `FollowMode.tsx`, `ImportReviewModal.tsx`

**Remediation:** Add `type="button"` to ALL `<button>` elements that are not explicit form submit buttons. Consider an ESLint rule (`eslint-plugin-jsx-a11y` has `button-has-type`) to enforce this automatically.

---

### C2. Icon-Only Buttons Missing Accessible Names
**Impact:** Screen readers cannot identify the purpose of icon-only buttons.  
**Files Affected:** 13 files, 22 occurrences  
**Key Locations:**
- `FindBar.tsx:75` — Close button (`<X />`) has `title` but no `aria-label`
- `NodeEditModal.tsx:54, 220` — Close and delete annotation buttons
- `pedigrees.tsx:187`, `patients.tsx:210`, `profiles.tsx:344` — Delete buttons (`<Trash2 />`)
- `VersionHistoryPanel.tsx:25, 59, 63` — Save, restore, delete version buttons
- `LanShare.tsx:183, 230, 294` — Close and copy buttons
- `ImportReviewModal.tsx:58`, `FollowMode.tsx:79`

**Remediation:** Add `aria-label` to every icon-only button. The `title` attribute is not sufficient for screen reader accessibility.

---

### C3. Inline Styles Bypassing the Theme System (95+ Occurrences)
**Impact:** Prevents theming consistency, breaks dark mode in edge cases, and complicates maintenance.  
**Files Affected:** 23 files  
**Worst Offenders:**
- `RibbonToolbar.tsx` — 11 inline styles (hardcoded heights, popover backgrounds, primary colors)
- `pedigree-share.tsx` — 13 inline styles with hardcoded hex colors (`#0a0a0a`, `#1f1f1f`, `#111`, `#0d0d0d`, `rgba(57,255,20,0.22)`)
- `RiskCalculatorPanel.tsx` — 11 inline styles with hardcoded health colors (`#FF4040`, `#FACC15`, `#888`)
- `NodeShape.tsx` — 6 inline styles for SVG text positioning
- `NodeEditModal.tsx` — 6 inline styles for color swatches and popover

**Remediation:**
1. Create CSS custom properties for all design tokens: blur radii, outline widths, shadow values, grid sizes, canvas font sizes, letter spacing, opacity levels.
2. Replace inline styles with Tailwind utility classes or CSS variable references.
3. For dynamic colors (annotation colors, health status), use CSS custom properties or data attributes, not inline `style={{ color: ... }}`.

---

### C4. Performance: Inline Objects/Arrays in JSX Props Causing Unnecessary Re-renders
**Impact:** Child components re-render on every parent render because inline objects fail referential equality.  
**Key Locations:**
- `pedigree-canvas.tsx:335` — `tabs={tabs.map((t: any) => ({ id: t.id, title: t.title }))}` creates fresh array + objects on every render
- `dashboard.tsx:102-108` — `stats={[{ label: "Total Patients", ... }, ...]}` fresh array on every render
- `RibbonToolbar.tsx` — `style={{...}}` objects recreated on every render (all 11 instances)

**Remediation:**
1. Memoize mapped arrays with `useMemo`.
2. Extract static arrays outside components.
3. Replace inline `style` objects with CSS classes where possible, or memoize style objects with `useMemo`.

---

### C5. Performance: Expensive Computations in Render Without Memoization
**Impact:** O(n²) algorithms run on every render, causing jank on large pedigrees.  
**Key Locations:**
- `PedigreeCanvasBody.tsx:207-232` — IIFE reconstructs parent-child family groups: `filter` → `Map` iteration → `sort()` on every render
- `PedigreeCanvasBody.tsx:251-278` — Per-annotation `filter(...)` + `findIndex(...)` for stack positioning: **O(n²)** where n = annotation count
- `ContextMenu.tsx:32-38` — Four separate array scans (`filter`, `some`, `some`, `find`) on every context menu render
- `SibshipGroup.tsx:15-16` — Nested `nodes.find(...)` inside `map()`: **O(m×n)**

**Remediation:** Wrap all expensive computations in `useMemo`. Pre-compute lookup maps (`Map<string, Node>`) rather than calling `.find()` inside loops.

---

### C6. Component Architecture: Monolithic Components Exceeding 300 Lines
**Impact:** Violates single responsibility principle, makes testing difficult, and increases bundle impact.  
**Key Locations:**
- `sidebar.tsx` — 725 lines (shadcn/ui primitive, acceptable but large)
- `RibbonToolbar.tsx` — 646 lines (should be split into: `NodeToolbarGroup`, `ConnectToolbarGroup`, `EditToolbarGroup`, `ViewToolbarGroup`, `ArrangeToolbarGroup`, `ClinicalToolbarGroup`, `CollaborationToolbarGroup`, `FileToolbarGroup`, `ShareToolbarGroup`)
- `pedigree-canvas.tsx` — 531 lines (orchestrator with 80+ state variables — extract into context/providers)
- `PedigreeCanvasBody.tsx` — 406 lines
- `ImportDialog.tsx` — 400 lines (extract step components: `UploadStep`, `PreviewStep`, `LegacyStep`, `SummaryStep`)
- `profiles.tsx` — 371 lines
- `NodeEditModal.tsx` — 325 lines

**Remediation:**
1. Split `RibbonToolbar.tsx` into one file per toolbar group.
2. Extract `pedigree-canvas.tsx` state into a `PedigreeEditorContext` using React Context + `useReducer`.
3. Convert `ImportDialog.tsx` into a step-based component with dedicated sub-components.
4. Split `profiles.tsx` into `ProfileList`, `ProfileCreateModal`, `ProfileImportSection`.

## 2. MAJOR SEVERITY FINDINGS

### M1. Inputs Without Programmatically Associated Labels
**Impact:** Screen readers cannot announce field purposes.  
**Files Affected:** 9 files  
**Key Locations:**
- `NodeEditModal.tsx:64-121` — Name, DOB, Age, Condition, Clinical Notes inputs lack `htmlFor`/`id` pairing
- `PropertiesPanel.tsx:98-208` — Bulk condition, name, age, condition single inputs
- `ImportDialog.tsx:279-320` — Pedigree Title, Link to Patient inputs/selects
- `ShareModal.tsx:88-98` — Recipient Public Key textarea
- `LanShare.tsx:223-293` — All textareas lack `id` paired with label's `htmlFor`

**Remediation:** Ensure every `<label>` has an `htmlFor` matching the input's `id`. Use the existing `<Label>` shadcn component consistently.

---

### M2. Heading Hierarchy Violations
**Impact:** Screen reader users rely on heading hierarchy for navigation. Missing or skipped levels break this.  
**Key Locations:**
- `pedigree-canvas.tsx` — No `<h1>` on the editor page
- `pedigree-share.tsx` — No `<h1>` on the share page
- `not-found.tsx` — "404" and "Page Not Found" are plain `<div>` elements, not headings
- `ErrorBoundary.tsx:43` — `<h2>` used without preceding `<h1>`
- `PedigreeCanvasErrorBoundary.tsx:40` — `<h2>` used without preceding `<h1>`

**Remediation:** Add `<h1>` to every page. Convert error boundary headings to proper hierarchy or use `<h1>` for the primary error message.

---

### M3. Divs Used as Interactive Elements Without Proper ARIA
**Impact:** Keyboard and screen reader users cannot access these interactive elements.  
**Key Locations:**
- `Layout.tsx:91-108` — `<div>` inside `<Link>` has `onClick`, `tabIndex={0}`, `role="link"` but no `onKeyDown`. Nested interactive elements.
- `Layout.tsx:159-164` — `<div>` inside `<Link>` with `onClick` but no `role` or `tabIndex`.
- `PedigreeCanvasBody.tsx:241, 262` — SVG `<g>` elements with `onClick` lack `role="button"` and `tabIndex`.

**Remediation:**
1. In `Layout.tsx`, remove the inner `<div>` click handlers; use `<Link>`'s native navigation or wrap in `<button>`.
2. For SVG interactive elements, add `role="button"`, `tabIndex={0}`, and `onKeyDown` handlers for Enter/Space.

---

### M4. Hardcoded Colors Throughout Canvas and UI Components
**Impact:** Colors do not adapt to theme changes, breaking dark/light mode consistency.  
**Files Affected:** 20+ files  
**Key Locations:**
- `pages/pedigree-share.tsx` — `rgba(255,255,255,0.35)`, `#0a0a0a`, `#1f1f1f`, `#111`, `rgba(57,255,20,0.22)` (14+ occurrences)
- `features/pedigree-editor/overlay/Minimap.tsx` — `rgba(8,8,8,0.82)`, `#FACC15`, `rgba(255,255,255,0.4)`
- `features/pedigree-editor/overlay/LegendPanel.tsx` — `rgba(255,255,255,0.6)`, `rgba(200,200,200,0.3)`, `rgba(8,8,8,0.92)`
- `features/pedigree-editor/panels/RiskCalculatorPanel.tsx` — `#FACC15`, `#FF4040`, `#888`
- `features/pedigree-editor/canvas/NodeShape.tsx` — `#FF4040`, `#00BFFF`, `rgba(255,64,64,0.07)`
- `features/pedigree-editor/canvas/types.ts` — `ANNOTATION_COLORS = ["#6475F7", ...]`
- `lib/generate-thumbnail.ts` — `#39FF14`, `#0A0A0A`, `#3A3A3A`, `#1E1E1E`, `#484848`, `#2A2A2A`, `#404040`, `#555`, `#666`
- `lib/export-pedigree.ts:1235` — `#0a0a0f`

**Remediation:**
1. Define all canvas colors in `theme.ts` as part of each theme object.
2. For health/status colors, create a `STATUS_COLORS` token map that adapts to the current theme.
3. For annotation colors, use CSS custom properties or pass theme-derived colors.
4. In `pedigree-share.tsx`, use `bg-background`, `border-border`, `text-foreground` Tailwind classes instead of hardcoded hex values.

### M5. Missing `useCallback` / `useMemo` for Stable References
**Impact:** Functions and computed values recreated every render, causing child re-renders and expensive recomputation.  
**Files Affected:** 8 files  
**Key Locations:**
- `profiles.tsx:71-136` — `handleExportProfile`, `handleImportProfile`
- `ImportDialog.tsx:60-182` — `processFile`, `handleFileInput`, `handleDrop`, `handleImport`, `handleLegacyImport`
- `dashboard.tsx:35-84` — `renderActivitySkeleton`, `renderActivityItems`, `renderLogSkeleton`, `renderLogItems`
- `pedigree-canvas.tsx:305-318` — `handleSaveVersion`, `commitSaveVersion`, `handleDeleteVersion`, `handleRestoreVersion`, `getExportInfo`, `he`
- `RibbonToolbar.tsx:128-131` — `openConfirm`

**Remediation:** Wrap all event handlers and render helpers in `useCallback`. Wrap all computed data structures in `useMemo`.

---

### M6. `requestAnimationFrame` Without Unmount Cleanup
**Impact:** If `PedigreeCanvas` unmounts during a drag operation, the rAF callback fires and calls `setCanvas` on an unmounted tree, causing React warnings and potential memory leaks.  
**Key Locations:**
- `use-pedigree-canvas.ts:122-135` — `rafRef.current = requestAnimationFrame(...)` scheduled during drag
- `pedigree-canvas.tsx:112` — `rafRef` created but no unmount cleanup

**Remediation:** Add a `useEffect` cleanup in `pedigree-canvas.tsx` (or the hook) that calls `cancelAnimationFrame(rafRef.current)` on unmount.

---

### M7. Responsive Design: Fixed Panel Widths Without Mobile Adaptation
**Impact:** Sidebars and panels overflow on narrow viewports, breaking mobile usability.  
**Key Locations:**
- `Layout.tsx:69` — `w-56` (224px) fixed sidebar width
- `PropertiesPanel.tsx:44` — `w-60` (240px) fixed right panel
- `VersionHistoryPanel.tsx:19` — `w-64` (256px) fixed panel
- `RiskCalculatorPanel.tsx:131` — `w-64` (256px) fixed panel
- `ValidationPanelWrapper.tsx:22` — `w-72` (288px) fixed panel
- `TabPickerPopover.tsx:43` — `w-64` popover width
- `ThemePicker.tsx:29` — `w-56` dropdown width

**Remediation:**
1. Use responsive Tailwind prefixes: `w-full md:w-60` for panels.
2. Convert panels to collapsible off-canvas drawers on mobile (`<Sheet>` component).
3. Make the canvas editor's right panels stack or become togglable overlays on narrow screens.

---

### M8. Very Small Fixed Font Sizes (`text-[9px]`, `text-[10px]`)
**Impact:** Below typical browser minimums, unreadable on high-DPI mobile screens, and fail WCAG 1.4.4 (Resize Text).  
**Files Affected:** 15+ files, 80+ occurrences  
**Worst Offenders:**
- `RibbonToolbar.tsx` — 40+ occurrences of `text-[9px]`, `text-[10px]` for group labels, button labels, dropdown items
- `ContextMenu.tsx` — `text-[9px]` for group headers and hints
- `NodeEditModal.tsx` — `text-[10px]` for modal labels and hints
- `VersionTimeline.tsx` — `text-[10px]` for timeline metadata
- `Layout.tsx` — `text-[10px]` for version label, profile role, online status

**Remediation:**
1. Replace `text-[9px]` with `text-xs` (12px) or `text-[10px]` with `text-xs`.
2. If smaller text is absolutely necessary for dense UI, ensure it is at least 10px and has high contrast (4.5:1 ratio).
3. Use `text-xs` consistently across the application for metadata and labels.

---

### M9. `maximum-scale=1` in Viewport Meta Tag
**Impact:** Prevents users from zooming, violating WCAG 1.4.4 and mobile usability best practices.  
**Location:** `index.html:5`

**Remediation:** Remove `maximum-scale=1` from the viewport meta tag. Use `width=device-width, initial-scale=1.0` only.

---

### M10. Missing `key` Props Using Array Index
**Impact:** React reconciliation issues when list items reorder, causing state bugs and unnecessary DOM mutations.  
**Key Locations:**
- `ImportDialog.tsx:275, 381` — `result.warnings.map((w, i) => <div key={i} ...>)`
- `RiskCalculatorPanel.tsx:52, 75, 205, 221` — `result.entries.map((e, i) => ...)` and `result.basis.map((b, i) => ...)`

**Remediation:** Use stable identifiers for keys. If the data genuinely has no stable ID, derive one from the content (e.g., `key={\`${e.label}-${i}\``) or add IDs to the data model.

## 3. MINOR SEVERITY FINDINGS

### m1. Inconsistent Spacing Values
**Impact:** Visual rhythm inconsistencies and maintenance difficulty.  
**Details:** The codebase mixes standard Tailwind spacing (`px-4`, `py-2`, `gap-3`) with arbitrary pixel values (`min-w-[44px]`, `w-[48px]`, `min-w-[220px]`) and fractional utilities (`mt-0.5`, `mb-1.5`, `pt-0.5`).

**Remediation:** Standardize on Tailwind's default spacing scale. For touch targets, use `min-h-11 min-w-11` (44px) consistently. For panels, use standard width utilities (`w-56`, `w-64`) without arbitrary values where possible.

---

### m2. CSS Specificity Anti-Patterns
**Impact:** Makes overrides difficult and increases maintenance burden.  
**Key Locations:**
- `styles/elevate.css:25, 29, 33-36, 41-44, 63-68` — Chained class selectors with pseudo-elements: `.toggle-elevate.toggle-elevated::before`, `.hover-elevate:not(.no-default-hover-elevate)::after`
- `components/ui/sidebar.tsx:236` — `group-data-[collapsible=icon]:w-[calc(var(--sidebar-width-icon)+var(--spacing-4)+2px)]`
- `components/ui/input-group.tsx:38, 85, 88` — `rounded-[calc(var(--radius)-5px)]`

**Remediation:** Replace overly specific selectors with data attributes or simpler class structures. Remove magic-number offsets (`+2px`, `-5px`) by adjusting the base tokens.

---

### m3. Hardcoded Magic Numbers
**Impact:** Unclear intent and inconsistent behavior across the app.  
**Key Locations:**
- `RibbonToolbar.tsx:137` — `height: "72px"`, `minHeight: "72px"`, `zIndex: 20`
- `TabBar.tsx:32` — `height: "44px"`, `minHeight: "44px"`
- `NodeShape.tsx:93-96` — `S / 2 + 13`, `S / 2 + 24`, `+ 14`, `+ 11` for text positioning offsets
- `styles/components.css:20` — `background-size: 40px 40px` (grid size)

**Remediation:** Extract magic numbers into named constants or CSS custom properties. Document the purpose of each offset.

---

### m4. `h-screen` / `min-h-screen` Usage Causing Mobile Toolbar Offset
**Impact:** `100vh` does not account for mobile browser dynamic toolbars, causing layout shifts.  
**Key Locations:**
- `pedigree-canvas.tsx:330, 333` — `h-screen`
- `dashboard.tsx:87` — `h-screen`
- `pedigree-share.tsx:118, 126, 150` — `h-screen`
- `Layout.tsx:51` — `min-h-screen`
- `ErrorBoundary.tsx:38` — `h-screen`
- `PedigreeCanvasErrorBoundary.tsx:35` — `min-h-screen`

**Remediation:** Replace `h-screen` with `h-dvh` (dynamic viewport height) where browser support is acceptable, or use `min-h-svh` (small viewport height) with fallback to `min-h-screen`. For the canvas editor, use a flex parent with `flex-1` instead of explicit viewport heights.

---

### m5. `any` Types in Production Code
**Impact:** Loses TypeScript's type safety guarantees.  
**Key Locations:**
- `pedigree-canvas.tsx:367` — `updateCanvas={updateCanvas as any}`
- `pedigree-canvas.tsx:378` — `saveVersion={saveVersion as any}`
- `pedigree-canvas.tsx:179` — `queryClient.setQueryData(queryKeys.pedigree(id), (old: any) => ...)`
- `pedigree-canvas.tsx:312` — `restoreVersion.mutate(..., { onSuccess: (d: any) => ... })`
- `pedigree-canvas.tsx:513` — `setCanvas(typeof data === 'string' ? parseCanvas(data) : data as CanvasData)`

**Remediation:** Replace all `any` types with proper interfaces or generics. For `queryClient.setQueryData`, use the pedigree type from `@workspace/db`.

---

### m6. Missing Focus Trap in Custom Dropdowns/Modals
**Impact:** Keyboard users can tab out of active menus/modals, breaking navigation flow.  
**Key Locations:**
- `RibbonToolbar.tsx` — All custom dropdowns (Nodes, Layout, Labels, Templates, Save, Export) lack focus traps.
- `ContextMenu.tsx` — Has arrow key navigation but no Tab focus trap or Home/End keys.
- `ConfirmDialog.tsx` — Custom modal (not using Radix Dialog) lacks focus trap and `Escape` key handling.

**Remediation:**
1. Replace custom dropdown implementations with Radix UI primitives (`DropdownMenu`, `Popover`) which provide focus traps, arrow navigation, and accessibility out of the box.
2. For `ConfirmDialog.tsx`, switch to the existing `Dialog` from `@radix-ui/react-dialog` instead of the custom implementation.

---

### m7. Print Stylesheet Anti-Patterns
**Impact:** `!important` in print styles is contextually justified but could be simplified.  
**Location:** `index.css:107-152`

**Remediation:** Review print styles for necessity of each `!important`. Most are justified for print overrides, but verify no unintended side effects.

---

### m8. Sidebar Component Uses Cookie Instead of Local Storage
**Impact:** In Tauri/desktop mode, `document.cookie` may behave unexpectedly; also, `localStorage` is more appropriate for UI state persistence.  
**Location:** `components/ui/sidebar.tsx:84`

**Remediation:** Replace `document.cookie` with `localStorage` for sidebar state persistence, or use a `useEffect` that reads from `localStorage` on mount.

---

### m9. `whitespace-nowrap` in Constrained Containers
**Impact:** Text overflow on narrow viewports.  
**Key Locations:**
- `components/ui/button.tsx:8` — `whitespace-nowrap` on all buttons
- `components/ui/badge.tsx:8` — `whitespace-nowrap` on badges
- `components/ui/select.tsx:20` — `whitespace-nowrap` on select trigger
- `RibbonToolbar.tsx:523` — Status label with `whitespace-nowrap`

**Remediation:** Pair `whitespace-nowrap` with `truncate` and a max-width, or remove `whitespace-nowrap` for mobile-friendly text wrapping.

---

### m10. Context Menu Positioning Without Resize Listener
**Impact:** Menu may extend off-screen if viewport resizes after opening.  
**Location:** `ContextMenu.tsx:42-43`

**Remediation:** Add a `useEffect` with a `resize` listener that recalculates `ax`/`ay` when the window dimensions change.

   - Effort: Low

### Phase 4: Theming & Visual Consistency (Week 4)
**Goal:** Eliminate hardcoded colors and establish a token-based design system.

1. **Create CSS custom properties for canvas rendering**
   - Blur tokens: `--blur-sm`, `--blur-md`, `--blur-lg`
   - Outline tokens: `--ring-width`, `--outline-width`
   - Shadow tokens: `--shadow-ring`, `--shadow-card`
   - Grid token: `--grid-size`
   - Font tokens: `--canvas-font-mono`, `--canvas-tracking`
   - Effort: Medium

2. **Create theme-aware status colors**
   - `STATUS_COLORS` map in `theme.ts` with `error`, `warning`, `success`, `info` tokens
   - Replace all `#FF4040`, `#FACC15`, `#888` with theme tokens
   - Effort: Medium

3. **Replace inline styles in `RibbonToolbar.tsx`**
   - Move heights to CSS classes (`h-[72px]` → `h-18` or custom class)
   - Replace `style={{ background: "hsl(var(--popover))" }}` with `bg-popover`
   - Effort: Medium

4. **Replace hardcoded colors in `pedigree-share.tsx`**
   - Use `bg-background`, `border-border`, `text-foreground`, `text-muted-foreground`
