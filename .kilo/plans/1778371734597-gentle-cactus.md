# Comprehensive Codebase Audit Plan

## Context

Following a major refactor that removed all server-side components (Express API, Postgres, Cloudflare Worker relay, OpenAPI specs), the project now supports only two modes: Tauri desktop and browser standalone. A new `lib/browser-backend/` package re-implements the Rust backend surface in TypeScript using sql.js WASM SQLite + IndexedDB persistence + Web Crypto API. New collaboration features were added to `artifacts/haplopainter/src/features/collaboration/`.

**Additional prerequisite**: The user has identified that the Git commit history is messy — all commits from `f615396` and earlier represent Replit agent work, after which local coding stripped Replit dependencies. The user wants to clean the commit history before proceeding with the audit fixes, but has no prior Git experience.

## Objective

1. **Git History Cleanup** — Determine the safest strategy to clean/squash/rewrite history given the user's skill level and current branch/remote state.
2. **Codebase Audit** — Perform a full 7-dimension audit, identify all issues with severity, and produce a structured findings report with an action plan.

## Phase 0: Git History Cleanup (Prerequisite)

### Context
- HEAD is currently `f6153966037fd93363a57f60dc225e7728d8aeee` (the final Replit agent commit).
- The working tree contains all local stripping/refactoring work (deletions of Replit artifacts, server removal, new browser-backend package, collaboration features) but **none of it is committed**.
- User is the sole owner of the repo; no other clones exist.
- Remote: `gitsafe-backup/main` exists and can be force-pushed safely.
- Local branch `replit-agent` exists and can be preserved as an archive if desired.

### Strategy: Fresh Orphan Branch
Because the user wants a completely fresh history while keeping the current code, the safest approach is:
1. Create a new orphan branch `main-fresh` from the current working tree.
2. Stage **all** changes (modifications, deletions, and untracked files) into a single commit.
3. Commit with a descriptive message: *"Initial commit — stripped Replit deps, serverless refactor, browser backend, collaboration"*.
4. Delete the old `main` branch and rename `main-fresh` → `main`.
5. Force-push the new `main` to `gitsafe-backup`.
6. Optionally preserve `replit-agent` as an archive branch, or delete it if the user wants total cleanup.

### Commands
```bash
# 1. Stage everything (including deletions and untracked files)
git add -A

# 2. Create orphan branch from this snapshot
git checkout --orphan main-fresh

# 3. Commit
git commit -m "Initial commit — stripped Replit deps, serverless refactor, browser backend, collaboration"

# 4. Remove old main and replace with fresh history
git branch -D main
git branch -m main-fresh main

# 5. Force-push to remote
git push gitsafe-backup main --force

# 6. Optional: remove archive branch if desired
git branch -D replit-agent
git push gitsafe-backup --delete replit-agent
```

### Risks & Mitigations
- **Risk**: Accidentally losing the old history permanently.
  - **Mitigation**: Keep `replit-agent` branch untouched until the user confirms the new history is correct. Do not delete `replit-agent` unless explicitly requested.
- **Risk**: Missing files in the initial snapshot.
  - **Mitigation**: Use `git add -A` to capture all tracked changes, deletions, and untracked files. Verify with `git status` after staging.
- **Risk**: `.gitignore` changes cause hidden files to be omitted.
  - **Mitigation**: The new `.gitignore` is already modified in the working tree and will be staged by `git add -A`. Any files listed in the new ignore rules that should be kept must be verified.

## Phase 2: Issue Triage & Severity Assignment

### Critical (Breaks functionality or introduces severe security risk)
1. `useGetSharedPedigree` tries to fetch from deleted `/api/share/${token}` endpoint → 404 in browser mode
2. Ed25519 private keys stored in `localStorage` (plaintext, XSS-vulnerable) instead of secure storage
3. Database encryption key exported as raw bytes to IndexedDB without passphrase wrapping
4. `share_pedigree` emits unencrypted base64 JSON of full pedigree data

### High (Significant bug, performance issue, or maintainability risk)
5. `@workspace/crypto` declared as `devDependency` in `lib/browser-backend/package.json` but used at runtime
6. `lib/api-client-react/package.json` lacks `@workspace/browser-backend` dependency declaration
7. Vite config still proxies `/api` to non-existent server
8. `backup_database`, `restore_database`, `rotate_key`, `import_pedigree_legacy` all throw "not implemented"
9. `lib/db/src/index.ts` uses top-level await with dynamic `await import()` — may break in bundlers that expect sync ESM

### Medium (Code smell, partial feature gap, or potential bug)
10. `computeCanvasDiff` deep equality via `JSON.stringify` is brittle
11. `LanShare` WebRTC may fail silently on complex LANs; no STUN fallback
12. `VersionTimeline` and `FollowMode` both manage independent interval timers — risk of double playback or leaks
13. `saveDb` interval (30s) is never cleared if `initDb` is called multiple times
14. `detectApiMode` uses unnecessary `typeof window !== "undefined"` check

### Low (Cosmetic, minor DX, or cleanup)
15. Missing `AGENTS.md` at project root
16. Stale TODO comments in `db.ts` about bundling migrations
17. `.gitignore` CRLF/LF warnings on many files
18. `console.log` in `LanShare.tsx` guest acknowledgment handler

## Phase 3: Action Plan — Fixes & Refactoring

### Major Actions (Must Do)
- **Fix Critical #1**: Remove dead `/api/share/${token}` fetch in `useGetSharedPedigree`; route through `apiCall("import_shared")` in browser mode, or delete the hook if share-by-URL is no longer supported.
- **Fix Critical #2**: Replace `localStorage.setItem` for private keys in `backend-client.ts` with `storeProfilePrivateKey` from `crypto-store.ts`.
- **Fix Critical #3**: In `crypto-store.ts`, do not export raw `CryptoKey` bytes to IndexedDB. Wrap the key with a passphrase-derived key or use Web Crypto `wrapKey` before storage.
- **Fix Critical #4**: Implement real encryption for `share_pedigree` using `sodiumSealBox` or `encryptForRecipient` from `@workspace/crypto`.
- **Fix High #5 & #6**: Correct `package.json` dependency declarations in `lib/browser-backend` and `lib/api-client-react`.
- **Fix High #7**: Remove `/api` proxy blocks from `vite.config.ts` (both `server.proxy` and `preview.proxy`).
- **Fix High #8**: Either implement `backup_database`, `restore_database`, `rotate_key` in browser backend, or remove the hooks/buttons from the UI to avoid user-facing errors.
- **Fix High #9**: Evaluate whether `lib/db/src/index.ts` top-level await is safe for the project's bundler (Vite); if not, refactor to explicit async initialization.

### Minor Actions (Should Do)
- **Fix Medium #10**: Replace `JSON.stringify` comparison in `compareNodeProperties` with a proper deep-equal utility or structured comparison.
- **Fix Medium #11**: Add `setInterval` cleanup and guard against duplicate initialization in `db.ts`.
- **Fix Medium #12**: Consolidate playback timer logic between `VersionTimeline` and `FollowMode`, or extract a shared `usePlayback` hook.
- **Fix Low #15**: Create/update `AGENTS.md` with the new two-mode architecture, build instructions, and security model.
- **Fix Low #17**: Address CRLF/LF warnings by normalizing line endings in `.gitattributes`.
