## R1 — PedigreeEditorContext Extraction

### Current State

`pedigree-canvas.tsx` (550 lines) is an orchestrator with:
- **48 useState** calls (canvas, selectedIds, history, future, dragging, isDragging, viewBox, panning, 10 panel toggles, 3 link-mode states, 7 UI states, etc.)
- **26 useCallback** functions (canvas operations: addNode, deleteSelected, undo, redo, export, node type/status changes, etc.)
- **8 useMemo** values (autoLabels, validation, searchMatches, generationRails, legendEntries, tabItems, etc.)
- **8 useEffect** hooks (draft sync, auto-save debounce, live layout, rAF cleanup, search highlighting, etc.)
- **86 props** passed to `PedigreeCanvasBody`

### Goal

Reduce `pedigree-canvas.tsx` to ~150 lines by moving all logic into `PedigreeEditorContext`. The context provides everything via a single `usePedigreeEditor()` hook.

### Architecture

```
PedigreeEditorProvider (context + reducer)
├── state: PedigreeEditorState    (all 48 state values)
├── dispatch: PedigreeAction     (reducer actions)
├── operations: PedigreeEditorOps (memoized callback functions)
└── derived: PedigreeEditorMemo   (memoized computed values)

usePedigreeEditor() → { state, ops, memo }
```

### Implementation Steps

1. **Define types** in `src/features/pedigree-editor/context/types.ts`
   - `PedigreeEditorState` — flattened object of all 48 state values
   - `PedigreeEditorAction` — discriminated union of all state mutations (SET_CANVAS, ADD_NODE, TOGGLE_PANEL, etc.)
   - `PedigreeEditorOps` — all 26 callback functions
   - `PedigreeEditorMemo` — all 8 memoized values

2. **Create reducer** in `src/features/pedigree-editor/context/reducer.ts`
   - Action types mapped to state transitions
   - 40+ action types (one per setState pattern)
   - Batch actions supported (multiple state changes in one dispatch)

3. **Create provider** in `src/features/pedigree-editor/context/PedigreeEditorProvider.tsx`
   - Wraps useReducer + useCallback + useMemo + useEffect
   - Accepts `id: number`, `pedigree`, `tabs` props (external data sources)
   - Exposes context via `usePedigreeEditor()` hook
   - Canvas operations (addNode, deleteSelected, undo, redo) derived from dispatch
   - Auto-save, draft sync, live layout effects inside provider
   - rAF cleanup inside provider

4. **Rewrite PedigreeCanvasBody** to accept 3 props from context
   - `state: PedigreeEditorState`
   - `ops: PedigreeEditorOps`
   - `memo: PedigreeEditorMemo`
   - (Currently 86 individual props → 3 grouped props)

5. **Rewrite pedigree-canvas.tsx** to use the context
   - Render `PedigreeEditorProvider` wrapping `PedigreeCanvasBody`
   - Use `usePedigreeEditor()` for RibbonToolbar props
   - Use `usePedigreeEditor()` for panel/modal props

### Files to Create
- `src/features/pedigree-editor/context/types.ts` (~100 lines)
- `src/features/pedigree-editor/context/reducer.ts` (~150 lines)
- `src/features/pedigree-editor/context/PedigreeEditorProvider.tsx` (~300 lines)
- `src/features/pedigree-editor/context/index.ts` (re-exports)

### Files to Modify
- `src/pages/pedigree-canvas.tsx` — rewrite from 550 → ~150 lines
- `src/features/pedigree-editor/PedigreeCanvasBody.tsx` — rewrite from 86 props → 3 props
- Remove `PedigreeCanvasBodyProps` interface entirely
- Update tests if any reference the old prop interface

### Effort: 2-3 days

## R2 — Canvas Overlay Collision Detection

### Current State

Three overlays positioned absolutely on the canvas:
- **Minimap**: `bottom-4 right-4 z-20`, 180×~116px
- **Legend** (collapsed): `bottom-4 left-4 z-10`, 36×36px (icon chip)
- **Legend** (expanded): `bottom-4 left-4 z-10`, 224×variable px
- **KeyboardShortcutHint**: `bottom-3 left-3`, baseline text, `pointer-events-none`

### Issue

When Legend is expanded (224px wide) and Minimap is visible (180px wide), on viewports < ~420px they could overlap. Currently they're positioned on opposite sides so this is rare.

### Implementation

1. **Create `CanvasOverlayManager` component** in `src/features/pedigree-editor/overlay/CanvasOverlayManager.tsx`
   - Wraps Minimap, Legend, KeyboardShortcutHint
   - Tracks expanded/collapsed state of Legend
   - When Legend is expanded and viewport is narrow (< 480px), collapse Minimap or move Legend above

2. **Simple collision avoidance logic:**
   ```
   if viewport < 480px && legendExpanded:
     minimap → collapsed (hidden, toggleable via button)
   ```

3. **Move Legend expanded state to manager** — currently managed inside LegendPanel.tsx via `useState`. The manager provides the expanded state and the Legend receives it as a controllable prop.

### Files to Create
- `src/features/pedigree-editor/overlay/CanvasOverlayManager.tsx` (~60 lines)

### Files to Modify
- `src/features/pedigree-editor/overlay/LegendPanel.tsx` — accept `expanded` + `onToggle` props instead of internal state
- `src/features/pedigree-editor/PedigreeCanvasBody.tsx` — replace direct Minimap/Legend/KeyboardShortcutHint with CanvasOverlayManager

### Effort: 2-3 hours

## R3 — Mobile Canvas Touch Support

### Current State

The canvas has no touch event handlers. Touch interactions on mobile devices fall through to browser defaults (pinch-zoom-scroll on the page, not the canvas).

### Required Touch Handlers

1. **Single finger drag** → pan the canvas (maps to `handleSVGMouseDown` + `handleMouseMove`)
2. **Two-finger pinch** → zoom in/out (maps to `handleWheel`)
3. **Single tap** → select node (maps to `handleNodeClick`)
4. **Double tap** → edit node (maps to `handleNodeDoubleClick`)
5. **Long press** → context menu (maps to `handleNodeContextMenu`)

### Implementation Approach

Use React's `onTouchStart`, `onTouchMove`, `onTouchEnd` events on the same SVG element that has mouse handlers.

1. **Add touch handler hooks** to `src/features/pedigree-editor/hooks/use-canvas-touch.ts`
   ```ts
   function useCanvasTouch({
     svgRef, getSVGCoords, handlePan, handleZoom,
     handleNodeClick, handleNodeDoubleClick, handleNodeContextMenu,
   })
   ```
   - Tracks touch count, initial positions, timestamps
   - Single finger: pan (SVG mouse handlers already do this — touch events need equivalents)
   - Pinch: track two finger distance delta → zoom
   - Tap: < 300ms, < 10px movement → node click
   - Double tap: < 500ms between taps → node double click
   - Long press: > 500ms hold → context menu

2. **Attach handlers** in `PedigreeCanvasBody.tsx`
   - Add `onTouchStart`, `onTouchMove`, `onTouchEnd` to the SVG element
   - Prevent default on touch events to stop browser zoom/scroll

3. **Increase hit targets for touch** — NODE_SIZE (44px) is already touch-friendly, but the Minimap and small buttons may need larger targets on touch devices.

### Files to Create
- `src/features/pedigree-editor/hooks/use-canvas-touch.ts` (~100 lines)

### Files to Modify
- `src/features/pedigree-editor/PedigreeCanvasBody.tsx` — add touch handlers to SVG element

### Effort: 4-6 hours

## Implementation Order

1. **R2 first** (Canvas overlay collision) — smallest, low risk, unblocks nothing
2. **R3 second** (Mobile touch) — medium, independent, doesn't affect existing mouse behavior
3. **R1 last** (PedigreeEditorContext) — largest, highest risk, blocked on nothing

### Alternative: Skip R1

The PedigreeEditorContext extraction is architecturally beneficial but functionally neutral — it doesn't fix bugs or add features, it reorganizes code. If time is constrained, deferring this to a dedicated refactoring sprint is reasonable. The current architecture (48 useState calls) works correctly.
