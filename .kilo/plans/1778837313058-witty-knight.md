### M10 — Wheel `preventDefault()` in passive mode (`usePedigreeCanvas.ts:213`)
React's `onWheel` wraps a passive listener in modern browsers, making `e.preventDefault()` a no-op when zoom-scrolling. **Fix:** Register a native `wheel` event listener with `{ passive: false }` via `useEffect` in `PedigreeCanvasBody.tsx`, call `e.preventDefault()` there, and forward it to the React handler. Or, detach the React `onWheel` and manage scroll entirely via native listener.

**Simpler fix:** Replace `onWheel={handleWheel}` on the `<svg>` with a ref-based approach:
```ts
useEffect(() => {
  const el = svgRef.current;
  if (!el) return;
  const handler = (e: WheelEvent) => { e.preventDefault(); /* ...zoom logic... */ };
  el.addEventListener("wheel", handler, { passive: false });
  return () => el.removeEventListener("wheel", handler);
}, []);
```

### M31 — Empty-state text at viewport center (`PedigreeCanvasBody.tsx:272-277`)
Currently uses `W/2`, `H/2` which corresponds to viewBox center — when the user pans, the text scrolls off-screen. **Fix:** Use the SVG's current `viewBox` position to compute center:
```tsx
<text x={viewBox.x + vbW / 2} y={viewBox.y + vbH / 2} ...>
```

### M41 — CSV parser quoted fields (`import-pedigree.ts:294`)
**Fix:** Replace the naive `row = lines[i].split(delimiter)` with a simple state-machine that handles quoted fields. Or add a dependency like `papaparse` for robust CSV parsing. For a zero-dep approach:
```ts
function parseCSVLine(line: string, delimiter: string): string[] {
  const result: string[] = [];
  let current = "", inQuotes = false;
  for (const ch of line) {
    if (ch === '"') { inQuotes = !inQuotes; continue; }
    if (ch === delimiter && !inQuotes) { result.push(current.trim()); current = ""; continue; }
    current += ch;
  }
  result.push(current.trim());
  return result;
}
```

## WORKTREE MERGE CONFLICT — STILL FAILING

**Root cause:** The worktree merge mechanism applies patches (diffs) from the base branch. These patches expect the files to be in their **original** state. Since we have 30+ modified files from our edits, every patch fails with "does not match index" because the working tree differs from the base.

The patches that DID apply cleanly (`FollowMode.tsx`, `VersionTimeline.tsx`, `RiskCalculatorPanel.tsx`, `VersionHistoryPanel.tsx`) are the files I edited in this session's new edits — everything else was modified in prior sessions and doesn't match the base.

### Resolution options:

**Option A — Commit first, then merge** (recommended)
```bash
# Stage and commit all our changes as a single work-in-progress commit
git add -A
git commit -m "fix: comprehensive audit fixes (critical, high, medium, low)"
# Now retry the worktree merge — patches will apply cleanly on top
```

**Option B — Stash, apply patches, pop**
```bash
git stash
# Worktree merge tool applies patches on clean files
# Then:
git stash pop
# Resolve any conflicts manually
```

**Option C — Reset and re-apply patches manually**
```bash
# Reset only the conflicting files to base
git checkout -- <list of conflicting files>
# Apply the worktree patches
# Re-apply our fixes manually
```

Choose Option A unless there's a reason not to commit.
