## 2. Baseline Commit on `main`

### 2.1 Unstage noise already tracked

Some files may already be tracked by git despite being in `.gitignore`. Remove them from the index (keeps files on disk):

```powershell
git rm --cached *.log 2>$null
git rm --cached fe-err.log api-err.log api-out.log fe-out.log 2>$null
git rm --cached data/db.sqlite 2>$null
git rm --cached .env.example 2>$null
```

### 2.2 Stage intentional changes

Stage everything that represents the current working codebase:

```powershell
git add -A
```

### 2.3 Unstage new noise if any slipped in

After staging, verify the index. Unstage anything matching the `.gitignore` patterns that is **not source code**:

```powershell
git reset -- *.log
git reset -- data/*.sqlite
```

### 2.4 Review the staged diff

```powershell
git diff --cached --stat
```

Expected: hundreds of source files, zero log files, zero SQLite databases, zero `target/` entries.

### 2.5 Commit

```powershell
git commit -m "chore: v0.1.0 baseline — Tauri desktop with local profiles

- Rust backend: SQLCipher SQLite, 37 Tauri commands, Ed25519 signatures
- Frontend: React pedigree editor, undo/redo, auto-layout, validation
- Crypto: @noble/ed25519, libsodium wrappers, AES-256-GCM
- Adapter layer: tauri/fetch dual mode for desktop vs web
- Drizzle schemas: dual-column migration (patients, pedigrees, versions, profiles)
- Import/Export: .hpcl native format, PDF/SVG/PPTX/JSON exports
- Remove Replit artifacts and mockup sandbox
- Activity log, version management with thumbnails, dashboard stats"
```

**Result**: `main` is now a clean, reproducible checkpoint. This commit hash is your "safe point."

## 4. Commit Strategy Inside the Feature Branch

Use **small, single-purpose commits**. Each commit should do one thing and be reversible independently.

**The order below is advisory, not mandatory.** It reflects dependency logic (e.g., you cannot wire the adapter to a browser backend before the backend exists). Skip, reorder, merge, or split commits as your workflow demands. The only invariant is the baseline commit on `main` and the branch isolation.

## 5. Merge Back to `main`

When the branch is stable and tested:

```powershell
git checkout main
git merge feature/serverless-collaboration --no-ff -m "release: v0.2.0 serverless collaboration

- Remove all server dependencies (Express, Postgres, Cloudflare relay)
- Browser standalone mode via sql.js + IndexedDB
- Visual diff and version timeline in pedigree editor
- Import review with merge/branch/reject
- LAN file sharing via WebRTC data channels
- Ed25519 provenance chain maintained across all modes"
```

The `--no-ff` creates a merge commit, preserving the feature branch history as a visible arc.

## 6. Emergency Reversions

| Situation | Command |
|---|---|
| **Undo last commit** (keep changes unstaged) | `git reset HEAD~1` |
| **Undo last commit** (destroy changes) | `git reset --hard HEAD~1` |
| **Abandon branch, return to main** | `git checkout main; git branch -D feature/serverless-collaboration` |
| **Restore single file from main** | `git checkout main -- path/to/file` |
| **See what a commit changed** | `git show --stat <commit-hash>` |
| **Compare branch to main** | `git diff main..feature/serverless-collaboration --stat` |

---

## 7. Verification Checklist

Before each commit, run:

- [ ] `git diff --cached --stat` — no `.log`, `.sqlite`, `target/`, `node_modules/` files staged
- [ ] Commit message starts with `feat:`, `fix:`, `refactor:`, `ui:`, `chore:`, or `docs:`
- [ ] Commit message body explains **why**, not just what
- [ ] One logical change per commit (if you see unrelated files, split)

After the baseline commit:
- [ ] `git log --oneline -3` shows your baseline at the top
- [ ] `git branch` confirms you are on `feature/serverless-collaboration`
- [ ] `git status` shows "nothing to commit, working tree clean"
