# Post-Refactor Audit Report — Pedigree PRO

Comprehensive audit of the Pedigree PRO codebase following the HaploPainter/Pedigree PRO rebranding and server-removal refactor. Findings are categorized by severity and component.

---

## CRITICAL (Will cause runtime failures or security vulnerabilities)

### C1. Tauri `frontendDist` path mismatch
- **File:** `artifacts/ppro/src-tauri/tauri.conf.json:10`
- **Issue:** `frontendDist` is `"../dist"` but Vite outputs to `dist/public` (set in `vite.config.ts:61`). Tauri desktop builds will serve from the wrong directory — the app window will be blank.
- **Fix:** Change `frontendDist` to `"../dist/public"` in tauri.conf.json, or change Vite's `outDir` to `"dist"`.

### C2. Missing `export_pedigree_ppro` command registration
- **File:** `artifacts/ppro/src-tauri/src/lib.rs:44-85`
- **Issue:** The Rust function `export_pedigree_ppro` is defined in `export.rs` and called by the frontend via `apiCall("export_pedigree_ppro", ...)`, but it's NOT registered in the `generate_handler![]` macro. Calling it in Tauri desktop mode will produce a runtime error "command export_pedigree_ppro not found".
- **Fix:** Add `commands::export_pedigree_ppro` to the handler list in `lib.rs` and add `#[tauri::command]` attribute to the function in `export.rs`.

### C3. `require()` calls in ESM modules — will throw `ReferenceError`
- **Files:** `lib/db/src/schema/pedigree_node_annotations.ts:10-12`, `lib/db/src/schema/pedigree_phenotypes.ts:10-12`, `lib/db/src/schema_sqlite_node_annotations.ts:15-19`, `lib/db/src/schema_sqlite_pedigree_phenotypes.ts:14-18`
- **Issue:** These files use `require()` inside `.references()` callbacks, but `package.json` declares `"type": "module"`. In ESM context, `require` is not defined and will throw `ReferenceError` at runtime when Drizzle evaluates foreign key references.
- **Fix:** Replace `require()` with static `import` at module top-level, or restructure to avoid circular dependency.

### C4. `drizzle.config.ts` uses `__dirname` in ESM module
- **File:** `lib/db/drizzle.config.ts:12,13`
- **Issue:** `__dirname` is not available in ESM modules. Since `lib/db/package.json` has `"type": "module"`, this will throw `ReferenceError: __dirname is not defined` when running `drizzle-kit push`.
- **Fix:** Replace with `import.meta.dirname` (Node 21+) or `fileURLToPath(import.meta.url)`.

### C5. `importShared()` missing `importer_key` parameter
- **File:** `lib/api-client-react/src/backend-client.ts:264-265`
- **Issue:** Frontend sends `{ share_token: shareToken }` but the Rust `import_shared` command requires both `share_token: String` AND `importer_key: String`. The missing parameter will cause a runtime error in Tauri mode.
- **Fix:** Add `importer_key` parameter to the `importShared` function and pass `{ share_token: shareToken, importer_key }`.

### C6. Tauri CSP missing `font-src` and `style-src` directives
- **File:** `artifacts/ppro/src-tauri/tauri.conf.json:25`
- **Issue:** CSP is `default-src 'self'; connect-src 'self'; img-src 'self' data: blob:` — no `font-src` or `style-src`. The project uses self-hosted `@fontsource` fonts and Tailwind CSS. Without `font-src 'self'` and `style-src 'self' 'unsafe-inline'`, fonts won't load and styles will break in Tauri webview.
- **Fix:** Add `font-src 'self'; style-src 'self' 'unsafe-inline'` to the CSP.

### C7. Path traversal vulnerability in import commands
- **File:** `artifacts/ppro/src-tauri/src/commands.rs:981-993, 1004-1009`
- **Issue:** `import_pedigree_native` and `import_pedigree_legacy` accept arbitrary `path: String` from the frontend and pass it directly to `std::fs::read_to_string(&path)` / `Connection::open(legacy_path)` with no path scope validation. A compromised frontend could read any file on the host.
- **Fix:** Validate that the path is within the app's data directory or the allowed documents directory, or use Tauri's `dialog` plugin for file selection instead of accepting raw paths.

### C8. Placeholder updater signing key
- **File:** `artifacts/ppro/src-tauri/tauri.conf.json:58`
- **Issue:** `"pubkey": "PLACEHOLDER_ED25519_PUBLIC_KEY_FOR_UPDATE_SIGNING"` — if a release is built, the updater cannot verify signatures. This is a supply-chain risk.
- **Fix:** Generate a real Ed25519 keypair, embed the public key, and sign releases with the private key.

### C9. `ensureArrayBuffer` produces wrong buffer for subarray views
- **File:** `lib/crypto/src/index.ts:291-293`
- **Issue:** `new Uint8Array(data).buffer` returns the entire underlying ArrayBuffer, not just the slice. If called with a subarray view (non-zero `byteOffset`), key derivation will use wrong data. The correct implementation (`toArrayBuffer` at lines 19-21) already exists in this file.
- **Fix:** Replace `ensureArrayBuffer` body with `return data.buffer.slice(data.byteOffset, data.byteOffset + data.byteLength) as ArrayBuffer;` or delegate to `toArrayBuffer`.

### C10. Non-standard HKDF in `deriveSealboxKey`
- **File:** `lib/crypto/src/index.ts:295-317`
- **Issue:** The custom HKDF is missing the RFC 5869 counter byte (`0x01`), producing output incompatible with any standard HKDF implementation. If the Rust backend ever needs to decrypt data encrypted by the browser (or vice versa), sharing will fail silently.
- **Fix:** Either adopt standard HKDF (RFC 5869) or document the custom KDF as intentionally non-standard and ensure both backends use identical derivation.

## HIGH (Functional bugs, type safety gaps, build problems)

### H1. `better-sqlite3` version conflict
- **Files:** `package.json` (root, `^12.9.0`) vs `lib/db/package.json:16` (`^8.1.0`)
- **Issue:** Two different major version ranges for the same dependency. The `@types/better-sqlite3@^7.6.13` aligns with v8, not v12. Pnpm hoisting will pick one version, likely breaking the other consumer.
- **Fix:** Remove `better-sqlite3` from root `package.json` (it's already in `lib/db`) and align the version to a single range, or use pnpm overrides.

### H2. Alpha Tauri plugin versions
- **File:** `artifacts/ppro/src-tauri/Cargo.toml:18-20`
- **Issue:** `tauri-plugin-dialog`, `shell`, and `updater` are all at `2.0.0-alpha`. Stable Tauri v2 has been available since late 2024.
- **Fix:** Update to stable `2.x` versions.

### H3. Missing database indexes in browser-backend + activity log audit
- **File:** `lib/browser-backend/src/db.ts:238-306`
- **Issue (indexes):** The inlined `MIGRATION_001` creates only 3 indexes, while the external `001_initial.sql` creates 11. Missing indexes for `patients(last_name, first_name)`, `pedigrees(creator_key)`, `pedigrees(updated_at)`, `pedigree_versions(saver_key)`, `activity_log(timestamp)`, and `activity_log(actor_key)` will cause slow queries on the browser backend with moderate data volumes.
- **Issue (activity log):** The "Currently Opened" section on the dashboard (`dashboard.tsx:148-162`) is misleadingly named — it shows pedigrees sorted by `updated_at` (recently *modified*), not recently *opened*. The activity log itself is NOT replaced — it's fully functional and actively written to by both backends (6 INSERT points each). However, React Query mutations for pedigree/profile CRUD don't invalidate the `["activity"]` query key, relying solely on 15s polling. The activity log is also the HIPAA audit trail per `docs/COMPLIANCE-HIPAA.md`.
- **Fix:**
  1. Add the 6 missing indexes to `db.ts` `MIGRATION_001` (or add a `MIGRATION_004`):
     ```sql
     CREATE INDEX IF NOT EXISTS idx_patients_name ON patients(last_name, first_name);
     CREATE INDEX IF NOT EXISTS idx_pedigrees_creator_key ON pedigrees(creator_key);
     CREATE INDEX IF NOT EXISTS idx_pedigrees_updated_at ON pedigrees(updated_at);
     CREATE INDEX IF NOT EXISTS idx_pedigree_versions_saver_key ON pedigree_versions(saver_key);
     CREATE INDEX IF NOT EXISTS idx_activity_log_timestamp ON activity_log(timestamp DESC);
     CREATE INDEX IF NOT EXISTS idx_activity_log_actor_key ON activity_log(actor_key);
     ```
  2. Rename the dashboard section from "Recently Opened" to "Recently Modified" (or add a true `last_opened_at` column).
  3. Add `["activity"]` query key invalidation to all pedigree/profile mutation `onSuccess` callbacks in `hooks.ts`.

### H4. Unimplemented browser-backend functions throw at runtime with no type guard
- **File:** `lib/browser-backend/src/commands.ts:799-810`
- **Issue:** `backup_database()`, `restore_database()`, and `rotate_key()` always throw in browser mode. The frontend calls them through `apiCall` with no guard for browser mode, so users get unhandled errors.
- **Fix:** Either implement the functions, add try/catch with user-facing error messages in the frontend hooks, or use conditional types that exclude browser-mode-unsupported commands.

### H5. Missing `creator_signature` and `saver_signature` in frontend types
- **File:** `lib/api-client-react/src/backend-client.ts:138-144, 186-191`
- **Issue:** `CreatePedigreeInput` is missing `creator_signature` and `SaveVersionInput` is missing `saver_signature`, both of which exist in the browser backend types. Provenance-signing features are impossible through the type-safe frontend API.
- **Fix:** Add `creator_signature?: string | null` to `CreatePedigreeInput` and `saver_signature?: string | null` to `SaveVersionInput`.

### H6. Stale `lib/integrations/*` glob in workspace config
- **File:** `pnpm-workspace.yaml:4`
- **Issue:** `- lib/integrations/*` references a non-existent directory. This was left over from server-side code removal.
- **Fix:** Remove the `lib/integrations/*` line.

### H7. `sql.js` version drift
- **Files:** root `package.json` (`^1.14.1`) vs `lib/browser-backend/package.json` (`^1.12.0`)
- **Issue:** Two different version ranges. The browser-backend is the actual consumer and should have the newer version, or versions should be aligned via catalog.
- **Fix:** Use `catalog:` reference in browser-backend, or update to `^1.14.1`.

### H8. `pg` dependency still present (dead code)
- **File:** `lib/db/package.json:19` (`"pg": "^8.20.0"`) and `lib/db/src/index.ts:50-74`
- **Issue:** All server-side code was removed per AGENTS.md, but the Postgres adapter code path and `pg` dependency remain. The Postgres branch in `index.ts` will fail at runtime if `DATABASE_URL` doesn't start with `sqlite:`.
- **Fix:** Remove `pg` and `@types/pg` from `lib/db/package.json`, and remove the Postgres code path from `index.ts`. Or document that it's intentionally retained for future compatibility.

### H9. `share_pedigree` command is a stub — implement full sharing
- **Files:** `artifacts/ppro/src-tauri/src/commands.rs:905-919`, `lib/browser-backend/src/commands.ts:546-603`, `lib/api-client-react/src/backend-client.ts:260-266`, `src/components/ShareModal.tsx`
- **Issue:** Tauri `share_pedigree` always returns `Err(...)` — the command calls `export_pedigree_ppro` but discards the result (`_ppro_json`). Sharing is a critical feature. Browser mode uses inline sealed-box tokens (no relay, no expiry, no revocation). The Rust relay client (`relay.rs`) is fully implemented but never wired up. `import_shared` in Rust passes raw ciphertext to `import_pedigree_ppro` without decrypting.
- **Implementation plan (frontend-orchestrated encryption):**

  **Step 1: Make Tauri `share_pedigree` return the `.ppro` JSON export**
  - `commands.rs`: Change `share_pedigree` to return `Ok(export_pedigree_ppro(...))` instead of `Err(...)`.
  - Update `ShareResult` struct or return the raw JSON string from `share_pedigree`.
  - The Rust side just exports; encryption stays client-side in the frontend.

  **Step 2: Create a new `relay_share` Tauri command**
  - New command `relay_share(payload: String, encrypted_key: String) -> Result<ShareResult, String>` that calls the existing `relay::share_encrypted_payload()` function.
  - This lets the frontend encrypt client-side then POST to relay via Rust (avoiding CORS issues).

  **Step 3: Create a new `relay_receive` Tauri command**
  - New command `relay_receive(token: String) -> Result<(String, String), String>` that calls `relay::fetch_shared_payload()` and returns `(ciphertext, encrypted_key)`.
  - Frontend decrypts using `sodiumOpenSealedBox`.

  **Step 4: Update `import_shared` in Rust**
  - Change `import_shared` to return raw `(ciphertext, encrypted_key)` tuple to frontend.
  - Move decryption to frontend: `sodiumOpenSealedBox(ciphertext, privateKey)`.
  - Then call a new `import_pedigree_from_json` command with the decrypted JSON.

  **Step 5: Fix browser `share_pedigree` to export full `.ppro` data**
  - `commands.ts`: Replace `get_pedigree()` call with `export_pedigree_ppro()` so version history, annotations, and phenotypes are included — not just the raw `Pedigree` record.

  **Step 6: Add relay integration for browser mode**
  - Add `relayShare(payload, encryptedKey)` and `relayReceive(token)` functions to browser-backend that POST to `https://relay.pedigreepro.app/api/relay/share` and `GET .../receive/{token}`.
  - Wire these into `share_pedigree` (POST encrypted data to relay, return share URL) and `import_shared` (fetch from relay, then decrypt).

  **Step 7: Add crypto to LanShare**
  - `LanShare.tsx`: Before sending over WebRTC data channel, encrypt with `sodiumSealBox`. Before receiving, decrypt with `sodiumOpenSealedBox`.

  **Step 8: Remove unencrypted base64 JSON fallback**
  - Remove the `atob` fallback in `import_shared` (`commands.ts:589-603`). Sharing now requires encryption.

  **Step 9: Export signing**
  - Wire `creator_signature`/`saver_signature` in `create_pedigree` and `saveVersion` frontend calls.
  - In `export.rs`, use the provided `exporter_key` to sign the export.

### H10. `beforeunload` cannot await async save
- **File:** `lib/browser-backend/src/db.ts:104-109`
- **Issue:** `saveDb()` is async but `beforeunload` event handlers can't await promises. Data loss of up to 10 seconds is possible on abrupt tab close.
- **Fix:** Consider `navigator.sendBeacon` for blob data, or use a `SharedWorker` / `ServiceWorker` pattern that survives page unload. Short-term: reduce the periodic save interval from 10s.

  - The `ShareResult.share_token` field (relay/encryption token) must stay — it's a different concept.
  - Update `backend-client.ts` `Pedigree` type to remove `share_token`.

### M8. Key wrapping stores wrapper + wrapped key together (obfuscation, not security)
- **File:** `lib/browser-backend/src/crypto-store.ts:139-161`

- **Fix:** Document that the no-passphrase path provides at-rest obfuscation only, not confidentiality. For real protection, require a passphrase or use WebAuthn-derived keys.
