# UI/UX Comprehensive Code Audit Plan

## Objective
Perform a comprehensive code audit of all UI and UX components in the `artifacts/haplopainter` frontend before committing changes. Review accessibility, responsive design, code quality, semantics, performance, and consistency. Document findings and resolve critical issues.

---

## Phase 1: Discovery & Static Analysis (Read-Only)

### 1.1 Accessibility Compliance Audit
**Files to review:** All `.tsx` components, especially interactive ones.

**Checklist:**
- [ ] **ARIA labels**: Verify all `<button>`, `<input>`, `<select>`, and icon-only controls have `aria-label` or associated `<label>`.
  - *Finding*: Icon-only buttons in `RibbonToolbar.tsx` (zoom, fit, snap, grid, minimap, undo, redo, delete) lack `aria-label`. They only have `title` attributes, which are insufficient for screen readers.
  - *Finding*: `DataTable.tsx` rows with `role="button"` lack `aria-pressed` and keyboard Enter/Space handling is minimal.
  - *Finding*: `ThemePicker.tsx` buttons for themes lack `aria-label` for color preview circles.
  - *Finding*: `TabBar.tsx` tab close buttons lack `aria-label="Close tab"`.
- [ ] **Keyboard navigation**: Ensure all interactive elements are reachable via Tab and operable via Enter/Space.
  - *Finding*: `ThemePicker.tsx`, `RibbonToolbar.tsx` dropdowns (more nodes, layout, labels, templates, export) don't trap focus or support Escape key closing consistently.
  - *Finding*: `ContextMenu.tsx` is mouse-only (right-click). No keyboard equivalent.
  - *Finding*: `FindBar.tsx` doesn't return focus to canvas on close.
- [ ] **Color contrast**: Verify all text/background pairs meet WCAG AA (4.5:1 for normal text, 3:1 for large/UI components).
  - *Finding*: `text-[9px]` and `text-[10px]` muted text (`text-muted-foreground`) against dark backgrounds needs verification. `--muted-foreground: 220 12% 55%` on `--background: 222 28% 6.5%` yields ~5.5:1 — acceptable.
  - *Finding*: `text-yellow-300/80` warnings on `bg-yellow-500/10` may fail contrast.
  - *Finding*: `text-emerald-400` success text on `bg-emerald-500/5` likely fails contrast.
- [ ] **Screen reader announcements**: Check for `aria-live` regions for loading/saving states.
  - *Finding*: Save status in `RibbonToolbar.tsx` (`"Saving…"`, `"Saved ✓"`) is visual-only. No `aria-live`.
  - *Finding*: `pedigree-canvas.tsx` loading state (`"LOADING..."`) lacks `role="status"`.
- [ ] **Focus management**: Verify focus is returned after modal/dropdown close.
  - *Finding*: `NodeEditModal`, `ContextMenu`, `ShareModal`, `ImportDialog` don't implement focus return or focus traps.

### 1.2 Responsive Design Audit
**Files to review:** `Layout.tsx`, `dashboard.tsx`, all page components, `use-mobile.tsx`.

**Checklist:**
- [ ] **Breakpoints**: Verify all layouts handle mobile (< 768px), tablet, and desktop.
  - *Finding*: `Layout.tsx` uses fixed `w-56` sidebar with no collapse/hide for mobile. `useIsMobile()` hook exists but is never used in `Layout.tsx`.
  - *Finding*: No hamburger menu or mobile navigation pattern.
  - *Finding*: `dashboard.tsx` uses `lg:grid-cols-3` but no `md:` or `sm:` grid adjustments. Single column on mobile may overflow.
- [ ] **Touch targets**: Verify minimum 44x44px touch targets.
  - *Finding*: `RibbonToolbar.tsx` buttons use `w-9 h-9` (36px) — below WCAG 2.1 minimum 44px.
  - *Finding*: `TabBar.tsx` tabs use `h-6` (24px) with small padding.
  - *Finding*: `ThemePicker.tsx` compact mode uses `w-3 h-3` icon.
- [ ] **Viewport/meta tags**: Verify `<meta name="viewport">` exists in `index.html`.
  - *Action*: Check `index.html` in the build directory.

### 1.3 Naming Conventions & Code Organization
**Checklist:**
- [ ] **File naming**: `use-mobile.tsx` uses kebab-case while other hooks use camelCase (`usePedigreeDraft.ts`, `use-toast.ts`). Inconsistent.
- [ ] **Component naming**: Most components use PascalCase correctly. OK.
- [ ] **Import aliases**: `@/` and `@workspace/` used consistently. OK.
- [ ] **Duplicated constants**: `NEON = "hsl(var(--primary))"` duplicated in `NodeShape.tsx`, `PedigreeCanvasBody.tsx`, `RibbonToolbar.tsx`, `TabBar.tsx`.
  - *Resolution*: Extract to shared constant `CANVAS_PRIMARY_COLOR` or use CSS custom property directly.
- [ ] **Magic numbers**: Hardcoded pixel values in `NodeShape.tsx` (e.g., `S / 2 + 16`, `S / 2 + 5`) should be named constants.

### 1.4 Code Smells & Redundancy
**Checklist:**
- [ ] **Large components**: `pedigree-canvas.tsx` is 414 lines with ~40 `useState` hooks. Should be refactored to `useReducer` or split into smaller state slices.
- [ ] **Inline JSX logic**: `pedigree-canvas.tsx` contains complex inline calculations and IIFEs in JSX. Move to helper functions.
- [ ] **Inline styles**: Mix of Tailwind classes and inline `style={{ ... }}` objects throughout. Choose one pattern or use a style utility.
- [ ] **Duplicated markup**: Loading skeletons are copy-pasted across `patients.tsx`, `pedigrees.tsx`, `profiles.tsx`, `dashboard.tsx`. Should use `TableSkeleton` or `CardSkeleton` consistently.
  - *Finding*: `dashboard.tsx` has inline `[...Array(5)].map(...)` skeletons instead of using shared `Skeleton.tsx` components.
- [ ] **Hook called in JSX**: `Layout.tsx` calls `useOnlineStatus()` directly in JSX (`{!useOnlineStatus() && ...}`). This creates a new hook call on every render and violates React Rules of Hooks.
  - *Critical*: Move to top-level variable before return.
- [ ] **Alert/Confirm usage**: `patients.tsx`, `pedigrees.tsx`, `profiles.tsx`, `patient-detail.tsx` use native `alert()` and `confirm()`. These are blocking, inaccessible, and inconsistent with the app's design system.
  - *Resolution*: Replace with `ConfirmDialog` component or toast notifications.

### 1.5 HTML Semantic Structure & CSS Specificity
**Checklist:**
- [ ] **Semantic elements**: Verify proper use of `<nav>`, `<main>`, `<aside>`, `<header>`, `<section>`, `<article>`.
  - *Finding*: `Layout.tsx` uses `<aside>` and `<nav>` correctly. OK.
  - *Finding*: `dashboard.tsx` uses `<div>` for cards that could be `<article>` or `<section>`.
- [ ] **Clickable divs**: Many `<div>` elements with `cursor-pointer` and `onClick` instead of `<button>`.
  - *Finding*: `DataTable.tsx` rows use `<div role="button">` — OK but could be `<button>` styled as row.
  - *Finding*: `dashboard.tsx` quick action items use `<div>` inside `<Link>`.
  - *Finding*: `pedigrees.tsx` list items use `<div>` instead of semantic list items.
- [ ] **Label associations**: Verify all form inputs have associated labels.
  - *Finding*: `ImportDialog.tsx` uses `<label>` but not `htmlFor`; relies on wrapper proximity.
  - *Finding*: `profiles.tsx` export/import passphrase inputs lack visible labels, only placeholders.
- [ ] **CSS specificity**: Check for overly specific selectors or `!important` usage.
  - *Finding*: `index.css` uses `!` in some utility classes. Tailwind v4 `@layer utilities` is used correctly.

### 1.6 Component Reusability & Modularity
**Checklist:**
- [ ] **Shared components**: `DataTable.tsx`, `PageHeader.tsx`, `SearchBar.tsx`, `EmptyState.tsx`, `ConfirmDialog.tsx` are well-abstracted.
- [ ] **UI primitives**: shadcn/ui components are used. OK.
- [ ] **Canvas components**: `NodeShape.tsx`, `EdgeLine.tsx`, `SibshipGroup.tsx`, `AnnotationShape.tsx` are modular. OK.
- [ ] **Hooks**: `usePedigreeCanvas.ts`, `usePedigreeKeyboard.ts`, `usePedigreeDraft.ts` are well-separated. OK.
- [ ] **Missing abstraction**: `ScrollFade` component in `dashboard.tsx` is inline and could be shared.

### 1.7 Error Handling & Loading States
**Checklist:**
- [ ] **Error boundaries**: `ErrorBoundary.tsx` exists and wraps the app. OK.
- [ ] **Loading states**: `isLoading` props used consistently with skeletons. OK.
- [ ] **Error states**: API errors often show inline text or `alert()`. Missing dedicated error UI components.
  - *Finding*: `ImportDialog.tsx` has inline error banners. Could use `Alert` component.
  - *Finding*: `ShareModal.tsx` error state uses raw text with emoji (`⚠`). Should use `Alert` or `AlertTriangle` icon consistently.
- [ ] **Empty states**: `EmptyState.tsx` exists but not used in all lists.
  - *Finding*: `dashboard.tsx` activity lists show plain text "No activity yet." instead of `EmptyState`.

### 1.8 Performance Optimization
**Checklist:**
- [ ] **Memoization**: Check `useMemo` and `useCallback` usage.
  - *Finding*: `pedigree-canvas.tsx` uses `useMemo` for `autoLabels`, `validation`, `searchMatches`. OK.
  - *Finding*: `generationRailEntries` and `legendEntries` use `useMemo`. OK.
  - *Missing*: `Layout.tsx` nav item active state check runs on every render. Could memoize.
- [ ] **Lazy loading**: No `React.lazy()` or `Suspense` boundaries for heavy components (pedigree canvas, modals).
  - *Action*: Add `React.lazy` for `PedigreeCanvas`, `ShareModal`, `ImportDialog`.
- [ ] **Image optimization**: No images in the app currently. OK.
- [ ] **Render-blocking**: Google Fonts loaded via `@import` in CSS (`index.css`). This blocks CSSOM construction.
  - *Action*: Move font loading to `<link rel="preconnect">` + `<link rel="stylesheet">` in `index.html`.
- [ ] **Animation performance**: `NodeShape.tsx` uses CSS `transition` on `transform`. GPU-accelerated. OK.
  - *Finding*: `animate-pulse` class causes repaint on opacity. Acceptable for skeletons.
  - *Missing*: No `prefers-reduced-motion` media query support for canvas animations.

### 1.9 Spacing, Typography & Design Tokens
**Checklist:**
- [ ] **Spacing consistency**: Verify consistent spacing scale.
  - *Finding*: Mix of `px-2`, `px-2.5`, `px-3`, `px-3.5`, `px-4`, `px-5` without clear rhythm.
  - *Finding*: Many `py-1`, `py-1.5`, `py-2` variations in `RibbonToolbar.tsx`.
- [ ] **Typography scale**: `text-xs`, `text-sm`, `text-base` used. OK.
  - *Finding*: Arbitrary font sizes `text-[9px]`, `text-[10px]` used heavily. Should use design token scale or ensure minimum 12px for accessibility.
- [ ] **Color tokens**: `hsl(var(--primary))` used correctly. OK.
  - *Finding*: Hardcoded hex values: `#FF4040` (error), `#00BFFF` (link source), `#FACC15` (warning). Should use CSS variables.
  - *Finding*: `text-red-400`, `text-yellow-400`, `text-emerald-400` used instead of semantic tokens (`text-destructive`, etc.).
- [ ] **Shadow tokens**: Custom shadow variables defined in `index.css`. OK.

### 1.10 Cross-Browser Compatibility
**Checklist:**
- [ ] **CSS features**: `backdrop-filter: blur(16px)` used in `.glass-panel`. Needs `-webkit-backdrop-filter` for Safari.
  - *Action*: Add vendor prefix.
- [ ] **Clipboard API**: `navigator.clipboard.writeText()` used in `ShareModal.tsx` and `profiles.tsx`. Needs fallback for insecure contexts.
- [ ] **SVG features**: Canvas uses SVG with no known compatibility issues. OK.
- [ ] **Font loading**: `JetBrains Mono` and `Inter` from Google Fonts. OK.

### 1.11 Debug Code & Console Statements
**Checklist:**
- [ ] `console.log`: None found.
- [ ] `console.error`: One instance in `ErrorBoundary.tsx` — acceptable for production error logging.
- [ ] `console.warn`: None found.
- [ ] Commented-out code: Search for `//` blocks that are dead code.
  - *Finding*: `ShareModal.tsx` has commented encryption protocol description. OK (documentation).
  - *Finding*: `theme.ts` has `// eslint-disable-next-line react-hooks/exhaustive-deps`. Acceptable.
- [ ] `debugger;` statements: None found.

### 1.12 State Management
**Checklist:**
- [ ] **Theme state**: `ThemeProvider` in `theme.ts` uses Context + localStorage + API. Well-structured. OK.
- [ ] **Pedigree canvas state**: ~40 `useState` hooks in `pedigree-canvas.tsx`. This is a maintainability risk.
  - *Recommendation*: Consolidate related state into objects or use `useReducer`.
  - *Finding*: UI toggles (`showVersions`, `showSaveModal`, `showShareModal`, etc.) could be grouped into a `uiState` object.
- [ ] **Draft persistence**: `usePedigreeDraft.ts` handles localStorage correctly. OK.
- [ ] **Tab state**: `usePedigreeTabs.ts` manages tab history. OK.
- [ ] **Query state**: TanStack Query used correctly with `invalidateQueries`. OK.

### 1.13 Focus States & Touch Targets
**Checklist:**
- [ ] **Focus rings**: Check `focus-visible:ring` usage.
  - *Finding*: `button.tsx` primitive has `focus-visible:outline-none focus-visible:ring-1 focus-visible:ring-ring`. OK.
  - *Finding*: Custom buttons in `patients.tsx`, `pedigrees.tsx`, `profiles.tsx` use raw `<button>` without `focus-visible:ring`. They only have `outline-none`.
  - *Finding*: `Layout.tsx` nav links use `<div>` with no focus ring.
  - *Finding*: `ThemePicker.tsx`, `RibbonToolbar.tsx` custom buttons lack focus rings.
- [ ] **Touch targets**: Minimum 44x44px.
  - *Finding*: Toolbar buttons are 36x36px. Need padding increase or minimum size enforcement.
  - *Finding*: Tab close button (`w-3 h-3`) is far too small.

### 1.14 Animation Performance & Motion Guidelines
**Checklist:**
- [ ] **GPU acceleration**: `transform` and `opacity` used for animations. OK.
- [ ] **Reduced motion**: No `prefers-reduced-motion` checks anywhere.
  - *Action*: Add `@media (prefers-reduced-motion: reduce)` rules to disable `animate-pulse`, canvas transitions, and dropdown animations.
- [ ] **Motion guidelines**: `transition-all duration-150` used widely. Specific transitions (`transition-colors`) preferred.
  - *Finding*: `transition-all` used in `Layout.tsx` nav items and many buttons. Should be `transition-colors` or specific properties.

## Phase 2: Critical Issue Resolution Plan

### Critical Issues (Must Fix Before Commit)
1. **HOOK-001**: `Layout.tsx` calls `useOnlineStatus()` inside JSX — violates React Rules of Hooks.
2. **A11Y-001**: Icon-only buttons across app lack `aria-label`.
3. **A11Y-002**: Native `alert()`/`confirm()` used for destructive actions — inaccessible and inconsistent.
4. **A11Y-003**: Touch targets below 44px in toolbar and tab bar.
5. **A11Y-004**: No `prefers-reduced-motion` support.
6. **PERF-001**: `pedigree-canvas.tsx` has ~40 `useState` hooks — consolidate into `useReducer`.
7. **CODE-001**: `NEON` constant duplicated in 4+ files.
8. **PERF-002**: Google Fonts `@import` blocks CSSOM.
9. **CSS-001**: `-webkit-backdrop-filter` missing for Safari glass panels.
10. **A11Y-005**: `DataTable.tsx` keyboard handling incomplete (Enter only, no Space).

### High Priority Issues
11. **RESP-001**: Sidebar has no mobile collapse behavior.
12. **A11Y-006**: Save status and loading states lack `aria-live`.
13. **CODE-002**: Loading skeletons duplicated instead of using shared components.
14. **A11Y-007**: Focus not returned after modal/dropdown close.
15. **DESIGN-001**: Hardcoded hex colors instead of design tokens.

### Medium Priority Issues
16. **CODE-003**: `transition-all` overused — should use specific properties.
17. **A11Y-008**: `text-[9px]` may be illegible on high-DPI screens.
18. **CODE-004**: `ScrollFade` component could be extracted.
19. **PERF-003**: No `React.lazy` for heavy routes.
20. **A11Y-009**: Context menu is mouse-only.

## Phase 3: Implementation Tasks

### Task 1: Fix Critical Hook Violation
**File**: `artifacts/haplopainter/src/components/Layout.tsx`
- Move `useOnlineStatus()` call to top-level before return statement.
- Store result in `const isOnline = useOnlineStatus();`
- Use `{!isOnline && (...)}` in JSX.

### Task 2: Add Accessibility to Icon-Only Buttons
**Files**: `RibbonToolbar.tsx`, `TabBar.tsx`, `ThemePicker.tsx`, `ShareModal.tsx`
- Add `aria-label` to all `<button>` elements that contain only icons.
- Ensure `title` attributes are preserved as supplementary.

### Task 3: Replace Native Alerts with Accessible Dialogs
**Files**: `patients.tsx`, `pedigrees.tsx`, `profiles.tsx`, `patient-detail.tsx`
- Replace `alert()` with toast notifications via `use-toast`.
- Replace `confirm()` with `ConfirmDialog` component.

### Task 4: Enforce Minimum Touch Targets
**Files**: `RibbonToolbar.tsx`, `TabBar.tsx`
- Increase toolbar button minimum size to `min-w-[44px] min-h-[44px]` or add padding to meet 44px.
- Ensure tab close button meets minimum size.

### Task 5: Consolidate Pedigree Canvas State
**File**: `pedigree-canvas.tsx`
- Group UI toggle states into `uiState` reducer.
- Extract canvas interaction state into separate hook or reducer.
- Target: Reduce `useState` count from ~40 to <15.

### Task 6: Extract Shared Constants
**Files**: `NodeShape.tsx`, `PedigreeCanvasBody.tsx`, `RibbonToolbar.tsx`, `TabBar.tsx`
- Create `src/lib/canvas-theme.ts` with `export const CANVAS_PRIMARY = "hsl(var(--primary))";`
- Replace all `NEON` local constants with import.

### Task 7: Add prefers-reduced-motion Support
**File**: `index.css`
- Add `@media (prefers-reduced-motion: reduce)` block.
- Disable `animate-pulse`, canvas node transitions, dropdown animations.

### Task 8: Optimize Font Loading
**File**: `index.css` / `index.html`
- Remove `@import url('https://fonts.googleapis.com/...')` from CSS.
- Add `<link rel="preconnect" href="https://fonts.googleapis.com">` and `<link rel="stylesheet">` in `index.html`.

### Task 9: Fix Safari Backdrop Filter
**File**: `index.css`
- Add `-webkit-backdrop-filter: blur(16px);` alongside `backdrop-filter`.

### Task 10: Improve DataTable Accessibility
**File**: `components/shared/DataTable.tsx`
- Add `aria-pressed` for selected rows.
- Add Space key support for row activation.
- Add `aria-label` to row buttons.

### Task 11: Add aria-live Regions
**Files**: `RibbonToolbar.tsx`, `pedigree-canvas.tsx`
- Wrap save status and loading indicators in `<span aria-live="polite">`.

### Task 12: Add Focus Management to Modals/Dropdowns
**Files**: `ShareModal.tsx`, `ImportDialog.tsx`, `ThemePicker.tsx`
- Use `useRef` + `useEffect` to focus first focusable element on open.
- Return focus to trigger element on close.
- Consider using Radix UI primitives (already used for Dialog, Tooltip, etc.) which handle this automatically.

### Task 13: Use Shared Skeleton Components
**Files**: `dashboard.tsx`, `patients.tsx`, `pedigrees.tsx`, `profiles.tsx`
- Replace inline `[...Array(5)].map(...)` skeletons with `TableSkeleton` or `CardSkeleton`.

### Task 14: Add Design Token Colors
**Files**: `NodeShape.tsx`, `ValidationPanel.tsx`, `RibbonToolbar.tsx`
- Replace hardcoded `#FF4040`, `#FACC15`, `#00BFFF` with CSS variables or Tailwind semantic colors.

### Task 15: Mobile Sidebar Collapse
**File**: `Layout.tsx`
- Use `useIsMobile()` hook to conditionally render sidebar.
- Add hamburger menu button for mobile.
- Slide-out sidebar drawer on mobile.

## Phase 4: Validation & Testing

### 4.1 Automated Checks
- Run ESLint with a11y plugin (`eslint-plugin-jsx-a11y`).
- Run `axe-core` or Lighthouse accessibility audit.
- Verify no console errors.

### 4.2 Manual Testing
- Tab through all interactive elements with keyboard only.
- Test with screen reader (NVDA/VoiceOver).
- Test on mobile viewport (320px width).
- Test with `prefers-reduced-motion: reduce` enabled.
- Verify color contrast with browser dev tools.

### 4.3 Performance Checks
- Verify fonts load via `<link>` not `@import`.
- Check bundle size impact of changes.
- Verify no layout thrashing in canvas animations.
