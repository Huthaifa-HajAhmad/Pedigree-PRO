## Audit Scope

HaploClinical / Pedigree PRO frontend (`artifacts/haplopainter/`): React 19.1 + Vite 7 + Tailwind CSS 4 + shadcn/ui (Radix) + TanStack React Query 5 + wouter + Recharts

## 1. Component Architecture & Reusability Patterns

### Strengths
- Clean feature-based architecture (`features/` for complex modules, `components/` for shared UI)
- shadcn/ui provides consistent headless+styled primitive layer via 27 Radix packages
- Single cross-cutting concerns directory (`hooks/`) with clear separation from features
- `components/shared/` provides app-specific reusable components (ErrorBoundary, DataTable, EmptyState, etc.)
- No props drilling issues -- React Query + local state eliminates the need

### Findings

| # | Severity | Finding |
|---|---|---|
| C1 | **Medium** | **No barrel exports in `features/pedigree-editor/` or most subdirectories.** `pedigree-canvas.tsx` has ~20 deep-path imports from `@/features/pedigree-editor/...` that could collapse to ~3 lines with proper barrel exports. |
| C2 | **Medium** | **Duplicate type definitions.** `PedigreeNode` is defined in 3 separate files (`canvas/types.ts`, `import-pedigree.ts`, `validate-pedigree.ts`) with slightly different field sets. The import version lacks `carrier` and `pregnancy` fields. |
| C3 | **Low** | **Mixed hook filename conventions.** `hooks/` has 3 files in kebab-case (`use-mobile.tsx`, `use-pedigree-tabs.ts`, `use-toast.ts`) and 2 in PascalCase (`usePedigreeDraft.ts`, `usePedigreeKeyboard.ts`). Standardize to kebab-case: `use-pedigree-draft.ts`, `use-pedigree-keyboard.ts`. |
| C4 | **Low** | **Empty dead files on disk.** `hooks/useVersionManagement.ts` (0 bytes) and `lib/canvas-theme.ts` (0 bytes) were deleted in commit `52d1957` but the files were not `git rm`'d. Should be removed from disk. |
| C5 | **Low** | **No feature-level ErrorBoundaries.** Only one app-level ErrorBoundary exists. Canvas-heavy features (pedigree-editor with Konva/react-konva) would benefit from per-feature boundaries to isolate SVG rendering crashes. |
| C6 | **Info** | **`framer-motion` is an unused dependency** (~5MB installed). Zero imports anywhere. It is a shadcn/ui boilerplate artifact -- the animation utilities it enables (accordion, collapsible, select transitions) are not wired up. Remove from package.json. |

## 2. CSS Methodology & Styling Approaches

### Current State
- **Tailwind CSS v4** (Vite-native `@tailwindcss/vite`, no PostCSS)
- **CSS custom properties** (`@theme inline`) for design tokens, HSL-based semantic colors
- **class-variance-authority** + `tailwind-merge` + `clsx` via `cn()` utility (shadcn/ui pattern)
- **6 pre-configured themes** via `data-theme` attribute on `<html>`
- **Single CSS file** (`src/index.css`, 608 lines) -- no CSS Modules, no SCSS
- **Radix UI primitives** as unstyled component base, styled with Tailwind

### Strengths
- Modern Tailwind v4 approach avoids PostCSS config complexity
- CSS custom properties are well-organized with semantic naming (`--primary`, `--muted-foreground`, etc.)
- Theme system supports 6 distinct themes with light/dark variants
- Custom `elevate` utility classes (`hover-elevate`, `active-elevate`) provide consistent hover/active states
- Glass morphism utilities (`.glass-panel`) for depth effects

### Findings

| # | Severity | Finding |
|---|---|---|
| S1 | **Medium** | **All 608 lines of CSS in a single file.** As the project grows, this becomes hard to maintain. Tailwind v4 supports `@import` for CSS modules -- theme blocks could be split into `src/styles/themes/*.css`. |
| S2 | **Medium** | **`@tailwindcss/typography` plugin loaded but potentially unused.** No `prose` class found on any element. If not used, remove the plugin to reduce CSS bundle. |
| S3 | **Low** | **Google Fonts loaded from CDN** (`fonts.googleapis.com`) in `index.html`. This is a privacy concern for a HIPAA-related clinical tool. Self-host Inter and JetBrains Mono via `@fontsource` packages. |
| S4 | **Low** | **No responsive design breakpoint system documented.** `use-mobile.tsx` checks `MOBILE_BREAKPOINT = 768` but there are no documented breakpoint tiers (sm/md/lg/xl). Add Tailwind breakpoint documentation. |
| S5 | **Low** | **Radix components use `import * as` pattern** (`import * as DialogPrimitive from "@radix-ui/react-dialog"`). This imports the entire module namespace and can bloat bundles. However, Radix packages are individually small enough that this has minimal impact. |
| S6 | **Info** | **No `prefers-contrast` or `prefers-color-scheme` beyond the basic `.dark` class.** The theme system is user-driven (manual picker), not system-preference-driven. |

### Action Items (Priority Order)
1. [S2] Verify `@tailwindcss/typography` usage; remove if unused
2. [S3] Replace Google Fonts CDN with self-hosted `@fontsource/inter` and `@fontsource/jetbrains-mono` for HIPAA privacy compliance
3. [S1] Split `index.css` into `styles/themes/terminal.css`, `clinical.css`, etc. + `styles/base.css` + `styles/utilities.css`
4. [S4] Document breakpoint system or add `useBreakpoint()` hook
5. [S6] Add `prefers-color-scheme` auto-detection as fallback for theme initialization

## 3. State Management Implementation

### Current State
- **React Query (`@tanstack/react-query`)**: Primary data layer for all CRUD (profiles, patients, pedigrees, versions, dashboard, sharing)
- **React Context**: 1 app-level (ThemeContext) + 6 shadcn/ui internal contexts (sidebar, form, chart, carousel, toggle-group, OTP)
- **localState**: 137+ `useState` calls for component-level UI state
- **localStorage**: 3 keys (theme, device ID, pedigree drafts, open tabs)
- **IndexedDB** (`idb-keyval`): 2 stores for encryption keys + database blobs (browser mode only)
- **React Hook Form + Zod**: Form state for create/edit operations
- **No external global state libraries** (no Redux, Zustand, Jotai, etc.)

### Strengths
- Clean server-state model: React Query cache IS the store, no duplication
- Mutations consistently invalidate relevant query keys on success
- localStorage draft management (`usePedigreeDraft.ts`) with cross-tab sync (`use-pedigree-tabs.ts` listens to `storage` events)
- Form state isolated to React Hook Form, not mixed with app state
- `useRef` for mutable references that shouldn't trigger re-renders (timers, WebRTC, drag state)

### Findings

| # | Severity | Finding |
|---|---|---|
| SM1 | **High** | **Inconsistent mutation error handling.** Some mutations have `onError` callbacks that show user feedback, others silently reset state (`setSaveStatus("idle")` in `pedigree-canvas.tsx` line 183). All mutations should at least show a toast on error. |
| SM2 | **Medium** | **`react-query` retry: 1 is very conservative.** Only 1 automatic retry with no exponential backoff. For a local SQLite backend (no network), retries are unlikely to help but exponential backoff would be appropriate for WebRTC sharing mutations. |
| SM3 | **Low** | **`localStorage` draft reads/writes use empty `catch {}` blocks** (18 instances across `theme.ts`, `usePedigreeDraft.ts`, `use-pedigree-tabs.ts`, `pedigree-canvas.tsx`, `usePedigreeCanvas.ts`). localStorage failures (quota exceeded, private browsing restrictions) are silently swallowed with no user feedback. |
| SM4 | **Low** | **`next-themes` installed but only used in `sonner.tsx`** (toaster theming). App uses custom `ThemeProvider` in `lib/theme.ts`. Either remove `next-themes` and replace sonner theming with the custom theme context, or adopt `next-themes` as the canonical theme provider. |
| SM5 | **Info** | **`react-query` staleTime: 10s is short for local data.** Data is read from local SQLite, not a remote API. A longer staleTime (30s-60s) would reduce unnecessary re-fetches without impacting freshness significantly. |
| SM6 | **Info** | **No optimistic updates.** Mutations wait for the backend to complete before updating cache. For a local SQLite backend (sub-millisecond), this is acceptable, but for sharing import operations it could feel slow. |

### Action Items (Priority Order)
1. [SM1] Audit all 16 mutations and ensure every one has a consistent error feedback mechanism (toast + inline error where appropriate)
2. [SM3] Create a `safeLocalStorage` utility that wraps get/set with proper error logging and fallbacks
3. [SM4] Choose one theme provider: either remove `next-themes` or adopt it canonically
4. [SM5] Increase `staleTime` to 30s for queries, 60s for dashboard stats
5. [SM2] Add exponential backoff to WebRTC sharing mutations

## 4. Performance Optimization Techniques

### Current State
- `useMemo` heavily used (~30 locations) for derived data (autoLabels, validation, searchMatches, legend entries, snap rows)
- `useCallback` used extensively (~46 in pedigree-canvas.tsx alone) for stable handlers
- `React.memo` on `NodeShape`, `EdgeLine`, and 2 pedigree-share components
- Dynamic `import()` for heavy optional deps (jspdf, pptxgenjs, crypto)
- No virtualization, no code splitting, no performance monitoring

### Findings

| # | Severity | Finding |
|---|---|---|
| P1 | **High** | **No route-level code splitting.** All 8 page components are statically imported in `App.tsx`. Large pages like `PedigreeCanvas` (with react-konva SVG rendering) are always in the initial bundle. Implement `React.lazy()` + `<Suspense>` per route. |
| P2 | **High** | **No version timeline virtualization.** `VersionTimeline.tsx` renders all version thumbnails in DOM. For pedigrees with 50+ saved versions, this creates 50+ `<img>` + DOM nodes. Implement `@tanstack/react-virtual` with fixed item height (~90px). **This is already called out in AGENTS.md L8.** |
| P3 | **Medium** | **No `manualChunks` strategy in Vite build config.** All vendor code (Radix UI, Recharts, date-fns, lucide-react) bundles together. Radix UI alone has 27 packages that could be a separate vendor chunk. |
| P4 | **Medium** | **Missing `loading="lazy"` and `decoding="async"` on `<img>` tags.** `VersionHistoryPanel.tsx` and `VersionTimeline.tsx` have `<img>` tags without these attributes. **AGENTS.md says they were added, but the actual code lacks them.** |
| P5 | **Medium** | **No performance monitoring.** No `web-vitals`, no `performance.mark()`/`performance.measure()`, no Lighthouse CI. Cannot track regressions. |
| P6 | **Medium** | **Missing `"sideEffects": false` in `package.json`.** This is the single most impactful omission for tree-shaking. Without it, bundlers assume all modules have side effects and cannot safely remove unused imports. This means all unused Radix UI packages, react-icons, date-fns, framer-motion, etc. bloat the bundle despite having zero imports. |
| P7 | **Low** | **No bundle analyzer.** Add `rollup-plugin-visualizer` to Vite config for ongoing bundle size monitoring. |
| P8 | **Low** | **`import * as` pattern for Radix/recharts** forces entire module into bundle. Change to named imports where possible, or at minimum add `sideEffects: false` so tree-shaking can eliminate them. |
| P9 | **Info** | **No build target/minify overrides.** Vite defaults are fine for modern browsers, but no `browserslist` or `build.target` is set, meaning Safari 15- users might not be supported. |

### Action Items (Priority Order)
1. [P6] **CRITICAL**: Add `"sideEffects": false` to `artifacts/haplopainter/package.json`
2. [P1] Implement `React.lazy()` + `<Suspense fallback={<Skeleton />}>` for all 8 page routes
3. [P2] Implement `@tanstack/react-virtual` on `VersionTimeline.tsx` (deferred from previous audit)
4. [P3] Add `build.rollupOptions.output.manualChunks` to separate vendor chunks (Radix UI, Recharts, lucide-react)
5. [P4] Add `loading="lazy"` and `decoding="async"` to `<img>` tags in `VersionHistoryPanel.tsx` and `VersionTimeline.tsx`
6. [P5] Integrate `web-vitals` for CLS, LCP, FCP, INP monitoring
7. [P7] Add `rollup-plugin-visualizer` with `open: false` for CI bundle analysis

## 5. Accessibility Compliance (WCAG Standards)

### Current State
- 75 `aria-*` attributes across 17 files (strong coverage)
- 53 `role=` attributes (thorough role definition)
- Keyboard navigation in ContextMenu (ArrowDown/Up/Right/Left, Escape, focus-visible rings)
- `.sr-only` utility used for screen-reader-only text (11 uses)
- `react-hook-form` + `@hookform/resolvers` provides `aria-describedby` and `aria-invalid` on form fields
- `prefers-reduced-motion` media query in `index.css`
- **No accessibility testing libraries** (no axe-core, jest-axe, Lighthouse CI, Pa11y)

### Findings

| # | Severity | Finding |
|---|---|---|
| A1 | **High** | **No accessibility testing infrastructure.** No `jest-axe`, `@axe-core/react`, or any automated accessibility auditing. No CI axe checks. Install `vitest-axe` or `jest-axe` and add at minimum one axe assertion per page. |
| A2 | **High** | **Heading hierarchy issues.** `ui/alert.tsx` uses `<h5>` for `AlertTitle`. If used after only `<h1>`-`<h3>` in context, this creates a heading level jump. Additionally, no audit of heading levels across pages exists. |
| A3 | **Medium** | **No skip-to-content link.** `Layout.tsx` has sidebar navigation as the first focusable element. Add a skip-link (`SkipToContent`) before the sidebar. |
| A4 | **Medium** | **No semantic sectioning elements.** No `<header>`, `<footer>`, `<section>`, or `<article>` elements used. The sidebar is `<aside>` and content is `<main>` (good), but page sections lack semantic wrappers. |
| A5 | **Medium** | **`placeholder`-only inputs.** Some form inputs rely on `placeholder` alone for labeling (placeholders disappear on focus, causing cognitive load). Ensure all inputs have `<label htmlFor>` or `aria-label`. |
| A6 | **Low** | **No `<dialog>` element usage.** All modals use Radix UI primitives (which handle their own accessibility well -- focus trapping, escape key, aria-modal), but native `<dialog>` would be worth evaluating. |
| A7 | **Low** | **Color contrast not audited.** No WCAG contrast checking tooling. Muted text (`text-muted-foreground`) on various background shades may fail minimum contrast ratios. Run axe-core audit to identify contrast issues per theme. |
| A8 | **Low** | **Canvas accessibility.** Pedigree nodes use `role="img"` + `aria-label` (good), but the canvas has no text alternative or data table view for screen reader users. This is inherently difficult for SVG-based editors but should be documented in AGENTS.md. |
| A9 | **Info** | **No `prefers-contrast` support.** Add `prefers-contrast: more` media query for high-contrast theme variant. |
| A10 | **Info** | **`aria-live` regions well-placed.** `aria-live="polite"` on save-status and offline banner, `role="status"` on loading spinners. Good pattern. |

### Action Items (Priority Order)
1. [A1] Add `vitest-axe` and write accessibility tests for all 8 page components
2. [A2] Replace `<h5>` in `AlertTitle` with `<p>` + heading styling, or audit all heading hierarchies
3. [A3] Add `SkipToContent` component at the top of `Layout.tsx`
4. [A4] Add `<header>`, `<section>` wrappers to page components
5. [A7] Run axe-core on all 6 themes and fix contrast issues
6. [A5] Audit all form inputs for proper label association
